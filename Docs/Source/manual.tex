\section{引言}

社区区域气候模式预处理系统（CRESM Preprocessing System，CPS）用于准备 新一代国产区域地球系统模式 CRESM 运行所需的输入数据。
CRESM 是一个多模式耦合系统，包含区域气候模式 CWRF 为基础，耦合了陆面模式 CoLM2024, 海洋模式 ROMS。

CPS 会调用各组件的前处理工具，生成 CWRF 的静态地理数据、初始场和侧边界驱动场，CoLM 的地表参数与初始场，以及 CPL7 耦合器的网格映射和插值权重文件。

运行前，用户需要在配置文件中设置实验区域、模拟时段和工具路径，并选择需要执行的处理步骤。

\begin{CPSEmphasis}[注意]
    请再正式开始使用CPS前，仔细阅读本手册，确保理解各处理步骤的功能和配置要求。

    \begin{center}
        \Large{\textbf{不报错不一定代表正确，代码永远会出错！！！}}
    \end{center}
\end{CPSEmphasis}


\section{系统环境要求}

CPS 主要在 Linux 平台运行。安装前需准备编译器、并行计算库、数据处理工具和 Python 环境，具体要求如下。

\subsection{操作系统要求}

推荐使用 Ubuntu 20.04 及以上版本。使用其他操作系统时，需先确认 CRESM 及其依赖工具能够运行。

\subsection{硬件配置要求}

推荐配置（具体需求取决于区域大小和数据规模）：

\begin{itemize}[leftmargin=4em]
    \item CPU：48核及以上
    \item 内存：100 GB RAM
    \item 磁盘空间：至少 100 GB 可用空间
\end{itemize}

\subsection{系统软件依赖}

运行前需安装以下软件：

\begin{itemize}[leftmargin=4em]
    \item Intel Fortran 编译器套件
    \item Intel MPI 并行环境
    \item NetCDF-C 与 NetCDF-Fortran 库
    \item HDF5 库
    \item netCDF Operator (NCO)
    \item Climate Data Operators (CDO)
    \item NCAR Command Language (NCL)
\end{itemize}

\begin{CPSNote}[Tips]
    加载运行环境后，检查以下命令是否可用：
    \begin{itemize}
        \item \texttt{mpirun}
        \item \texttt{ncdump}
        \item \texttt{ncl}
    \end{itemize}
\end{CPSNote}


\subsection{Python 运行环境}

CPS 使用 Python 3.9 及以上版本，环境安装方法见第 5.1 节。

主要依赖库包括：

\begin{itemize}[leftmargin=4em]
        \item numpy
        \item pandas
        \item matplotlib
        \item cartopy
        \item Pillow
        \item geopandas
        \item fiona
        \item esmpy
        \item esmf
        \item xesmf
        \item pyhdf
        \item pyparsing
        \item python-dateutil
\end{itemize}

\subsection{模式系统依赖}

运行 CPS 前，需编译并配置以下组件：

\begin{itemize}[leftmargin=4em]
    \item 区域气候模式 CRESM
    \item 区域气候模式CWRF的前处理套件(CWPS)
\end{itemize}

这些组件应能独立运行。CRESM\_ToolBox 提供相关工具和安装脚本，使用方法见第~\ref{CRESM 工具箱安装}~节。

\subsection{运行环境配置要求}

推荐使用单独的环境配置文件（例如: \linecode{~/.bashrc_cresm}）管理CPS运行环境。

\section{目录结构}

\subsection{项目根目录结构}

CPS 项目目录结构如下：

\subsection{核心程序目录（PrepScript）}

\begin{CPSCode}[leftmargin=2em]
    PrepScript/
        ├── CRESM_Preprocessing_System.py   # 主入口程序
        ├── case.ini                        # 实际实验配置
        ├── env.ini                         # 实际环境配置
        ├── Config/                         # 配置参考文件
        │   ├── case.ini.template           # 实验配置模板 [SYSU@Land 服务器]
        │   ├── env.ini.gnu_tms             # GNU TMS 编译环境模板 [SYSU@Land 服务器]
        │   ├── env.ini.gnu_hydro           # GNU Hydro 编译环境模板 [SYSU@Land 服务器]
        │   └── env.ini.intel               # Intel 编译环境模板 [SYSU@Land 服务器]
        ├── Modules/                        # Python 前处理模块
        │   ├── PrepCWRF.py                 # CWRF 前处理模块
        │   ├── PrepCoLM.py                 # CoLM 前处理模块
        │   ├── PrepCRESM.py                # CPL7 映射文件生成模块
        │   └── Utils/                      # 公共工具库
        │       ├── Consts.py               # 常量定义
        │       ├── ICBC.py                 # IC/BC 处理模块
        │       ├── Logger.py               # 日志处理模块
        │       ├── Tools.py                # 通用工具模块
        │       └── Domain.py               # 独立研究区域诊断模块
        └── Resources/                      # 模板、外部脚本与驱动信息
            ├── Forcing/                    # 驱动数据相关信息
            ├── NML/                        # namelist 模板
            └── ProcessScript/              # 处理脚本模板
\end{CPSCode}

功能说明：

\begin{itemize} [leftmargin=4em]
    \item \linecode{CRESM_Preprocessing_System.py} 系统主入口脚本，负责流程调度与模块调用。
    \item \linecode{PrepCWRF.py} 用于执行 CWRF 静态数据处理、IC/BC 生成等流程。
    \item \linecode{PrepCoLM.py} 负责陆面模式 CoLM 的基础数据准备与初始场构建。
    \item \linecode{PrepCRESM.py} 用于生成耦合器所需的网格映射和插值权重文件。
    \item \linecode{Domain.py} 用于基于 ERA5 等诊断数据计算异常场、相关系数和显著性研究区域。
\end{itemize}

\section{CPS流程总览}

CPS 会按需调用 PrepCWRF、PrepCoLM 和 PrepCRESM。各模块的全流程处理内容如下：

\begin{CPSCode} [leftmargin=4em,commandchars=\\\{\}]

            case.ini + env.ini                # 用户配置文件
                     ↓
        ┌──────────────────────────┐
        │  CRESM Preprocessing     │          # 主程序
        │        System            │
        └──────────────────────────┘
                     ↓
        ┌──────────────────────────┐
        │  PrepCWRF                │          # 准备CWRF所需数据
        │  - Domain Visualization  │          # 可视化研究域
        │  - Static Geogrid        │          # geogrid
        │  - Vegetation Parameters │          # 植被参数(FVC, LAI, SAI)
        │  - Initial/Boundary Data │          # 初始场/侧边界驱动场
        └──────────────────────────┘
                     ↓
        ┌──────────────────────────┐
        │  PrepCoLM                │          # 准备CoLM所需数据
        │  - Mesh Generation       │          # 制作映射文件
        │  - Surface Data          │          # 准备CoLM的陆面数据
        │  - Initial Conditions    │          # 初始化CoLM
        │  - Spin-up & Remapping   │          # Spin-up和重网格
        └──────────────────────────┘
                     ↓
        ┌──────────────────────────┐
        │  PrepCRESM               │          # 准备CRESM所需数据
        │  - Coupler Mapping Files │          # 耦合器权重文件
        └──────────────────────────┘

\end{CPSCode}

\section{安装与部署}

\subsection{Python 环境部署}

CPS 使用三个 Conda 环境，分别用于常规前处理、网格映射和 MODIS 数据处理。进入 CRESM\_ToolBox 中环境配置文件所在的目录，执行：

\begin{CPSCode} [leftmargin=2em,commandchars=\\\{\}]
    # 安装 cresm 环境 [主环境]
    conda env create -f cresm.yml

    # 安装 cresm_xesmf 环境 [网格映射环境]
    conda env create -f cresm_xesmf.yml

    # 安装 Chaomodis 环境 [MODIS 数据处理环境]
    conda env create -f Chaomodis.yml
\end{CPSCode}

\subsection{CRESM 工具箱安装}\label{CRESM 工具箱安装}

CRESM\_ToolBox 包含 CWRF 前处理系统 CWPS、陆面数据处理脚本及相关数据。安装前，需要在 \linecode{Makeoptions.ini} 中填写各依赖库的安装路径：

\begin{CPSCode} [leftmargin=2em,commandchars=\\\{\}]
    [LIBPATHS]
    NETCDF_path = $software/netcdf-single-r        # netcdf 安装目录
    JASPER_path = $software/jasper                 # jasper 安装目录
    PNG_path    = $software/libpng                 # libpng 安装目录
    ZLIB_path   = $software/zlib-1.2.11            # zlib 安装目录
\end{CPSCode}

填写路径后，在安装脚本所在目录执行：

\begin{CPSCode} [leftmargin=2em,commandchars=\\\{\}]
    python SetupAll.py
\end{CPSCode}

\section{基本用法}

\subsection{使用前准备}

在运行 CRESM 数据前处理系统之前，请完成以下准备工作：

\begin{enumerate}
    \item 确认系统环境已正确配置
    \begin{itemize}
        \item 确认 \linecode{env.ini} 中所有路径与环境的配置；
        \item 确认CWRF、CoLM 和 Conda 环境均可正常激活；
        \item 确认外部程序（如 ncl、cdo、ncks）可在命令行调用。
    \end{itemize}

    \item 确认实验配置文件已准备
    \begin{itemize}
        \item 参考 \linecode{Config/case.ini.template}，正确填写 \linecode{case.ini} 中的具体实验案例；
        \item 核对 \texttt{ForcingDataName} 与 \linecode{env.ini} 中对应的 forcing 配置一致；
        \item 检查模拟时间、网格参数、分辨率等关键信息。
    \end{itemize}
\end{enumerate}

\begin{CPSEmphasis}[！请重视！]
    以上检查直接决定了你能否顺利运行CPS，请十分重视！！！
\end{CPSEmphasis}


\subsection{命令行参数说明}

在主程序所在目录(\linecode{PrepScript/})执行以下命令，可查看命令行参数：

\begin{CPSCode} [leftmargin=2em,commandchars=\\\{\}]
    python CRESM_Preprocessing_System.py -h
\end{CPSCode}


\subsubsection{\texttt{-v,\ --version}}
显示程序版本信息并退出。反馈运行问题时，最好是同时提供该命令输出的版本号。
\begin{CPSCode} [leftmargin=2em,commandchars=\\\{\}]
    python CRESM_Preprocessing_System.py -v
\end{CPSCode}


\subsubsection{\texttt{-ch,\ --confighelp}}
打印 \linecode{case.ini} 和 \linecode{env.ini} 的配置项说明。
\begin{CPSCode} [leftmargin=2em,commandchars=\\\{\}]
    python CRESM_Preprocessing_System.py -ch
\end{CPSCode}


\subsubsection{\texttt{-l,\ --listcases}}
列出 \linecode{case.ini} 中可用的实验案例名称。
\begin{CPSCode} [leftmargin=2em,commandchars=\\\{\}]
    python CRESM_Preprocessing_System.py -l
\end{CPSCode}


\subsubsection{\texttt{-n\ NAME,\ --gridname\ NAME}}
指定要运行的案例。\texttt{NAME} 必须与 \linecode{case.ini} 中的某个实验小节名称一致。
\begin{CPSCode} [leftmargin=2em,commandchars=\\\{\}]
    python CRESM_Preprocessing_System.py -n CN_15km
\end{CPSCode}


\subsubsection{\texttt{-g\ DIR,\ --geogdir\ DIR}}
使用已有的 CWRF 地理静态数据目录，跳过 \texttt{Geogrid/FVC/LAI/SAI} 等静态地理数据生成步骤，直接使用 DIR 中已有的数据。 
\begin{CPSCode} [leftmargin=2em,commandchars=\\\{\}]
    python CRESM_Preprocessing_System.py -n CN_15km  -g /path/to/Geog_[GridName]
\end{CPSCode}

通过 \linecode{Geog_[GridName]} 中的 \linecode{Geog.ID} 文件核对网格配置；不同网格的数据不能混用。

\linecode{Geog.ID} 内容示例：
\begin{CPSCode}[leftmargin=2em,commandchars=\\\{\}]
    X[232]_Y[172]_dx[30000.000000]_dy[30000.000000]_lat[35.177800]_lon[110.000000]_
    tl1[30.000000]_tl2[60.000000]_slon[110.000000]_bw[15]_lk[0.500000]
\end{CPSCode}


\subsubsection{\texttt{-s\ DIR,\ --colmsrf\ DIR}}

使用已有的 CoLM 地表数据目录，跳过 \texttt{PrepCoLM} 中的地表数据生成流程\texttt{MakeSrf}，不同网格的数据不能混用。
\begin{CPSCode} [leftmargin=2em,commandchars=\\\{\}]
    python CRESM_Preprocessing_System.py -n CN_15km -s /path/to/CoLMSrf_[GridName]
\end{CPSCode}

通过 \linecode{CoLMSrf_[GridName]} 中的 \linecode{Geog.ID} 文件核对网格配置。多个案例使用相同网格和define 配置时，可复用这套地表数据
\begin{CPSEmphasis}[!请重视!]
    CoLM的namelist中部分选项可能会影响\texttt{MakeSrf}的结果，此项在CPS中不会进行检查，\textbf{所以这是你的责任！！！}
\end{CPSEmphasis}


\subsubsection{\texttt{-y\ YEAR,\ --year\ YEAR}}

将案例的起止时间平移到指定年份，生成新案例 \texttt{[GridName].year}。\texttt{YEAR} 为四位整数，例如 \texttt{2023}。
\begin{CPSCode} [leftmargin=2em,commandchars=\\\{\}]
    python CRESM_Preprocessing_System.py -n CN_15km -y 2023 
\end{CPSCode}

平移时保留原配置的月、日和时刻。原时段的起止年份相同或相差 1 年时，以起始年份为基准；相差 2 年时，以中间年份为基准。
例如，原时段为 1999 年 12 月 1 日至 2001 年 1 月 5 日，指定 \texttt{-y 2023} 后，时段变为 2022 年 12 月 1 日至 2024 年 1 月 5 日。
使用该功能时，请核对时间是否正确，有时会有问题。

\subsubsection{\texttt{-c\ NAME,\ --collectcase\ NAME}}

年度模式下的数据汇总参数（与 \texttt{--year} 一起使用）。
将多个年度的强迫数据汇总到同一目录 NAME，每个文件自动追加年份后缀。
先用 \texttt{--year} 完成各年份的处理，再单独运行收集命令
\begin{CPSCode} [leftmargin=2em,commandchars=\\\{\}]
    python CRESM_Preprocessing_System.py -c CN_15km 
\end{CPSCode}

\subsubsection{\texttt{-D,\ --domain}}

运行独立研究区域诊断分析。当你不知道研究区范围需要选择哪里时使用。该选项调用 \linecode{Domain.py}，使用 \linecode{env.ini} 的 \texttt{[Domain]} 配置读取诊断数据，依次生成月异常场、 研究区域相关系数、相关系数图以及显著性研究区域图。
它不执行常规前处理步骤，也不改变已有的模式输入文件。

研究区域必须通过以下两种方式之一指定：

\begin{itemize}[leftmargin=4em]
    \item \texttt{-ds\ SHP} 或 \texttt{-DS\ SHP}：使用 Shapefile文件指定核心研究区。
    \item \texttt{-db\ LON\_MIN\ LON\_MAX\ LAT\_MIN\ LAT\_MAX} 或大写别名 \texttt{-DB}：使用经纬度矩形框。
\end{itemize}

示例：

\begin{CPSCode}[leftmargin=2em,commandchars=\\\{\}]
    python CRESM_Preprocessing_System.py -n Yangtze_C_6km_MPI -D -db 90 120 20 35
    python CRESM_Preprocessing_System.py -n Yangtze_C_6km_MPI -D -ds /path/to/study_area.shp
\end{CPSCode}

两种边界同时提供时，Shapefile 优先级更高。诊断结果保存在案例目录的 \linecode{Case/[GridName]/Domain/} 下；
其中包括异常场和相关系数文件，以及 \linecode{Correlation_Plots/}、\linecode{Study_Area_Plots/} 两类图像。


\subsubsection{\texttt{-d,\ --debug}}
启用调试模式，在日志中记录路径检查、环境检查和各步骤调用的外部命令。排查运行错误时可以添加此参数，平时不建议使用。
\begin{CPSCode} [leftmargin=2em,commandchars=\\\{\}]
    python CRESM_Preprocessing_System.py -n CN_15km -d
\end{CPSCode}

在 \linecode{case.ini} 中配置 \texttt{CN\_30km} 案例后，执行：

\subsection{创建运行案例}

CPS 输出的数据可供\linecode{Create_Run_From_CPS.py} 创建 CRESM 运行案例。后者的命令行参数如下：

\begin{CPSCode}[leftmargin=2em,commandchars=\\\{\}]
    Create run directory for CRESM

    optional arguments:
      -h, --help            show this help message and exit
      -casename CASENAME, --casename CASENAME
                            name for entire run
      -casedir CASEDIR, --casedir CASEDIR
                            The parent directory where the case will be created
      -griddir GRIDDIR, --griddir GRIDDIR
                            Full path to Grid directory
      -icbcdir ICBCDIR, --icbcdir ICBCDIR

      -st STARTTIME, --starttime STARTTIME
                            YYYYMMDDHH
      -et ENDTIME, --endtime ENDTIME
                            YYYYMMDDHH
      -ncpus NCPUS, --ncpus NCPUS

\texttt{casename} 设置案例名称，\texttt{casedir} 指定创建案例的目录。
\texttt{griddir} 指定静态数据目录 \linecode{Grid_[GridName]}，\texttt{icbcdir} 指定 CWRF 初始场和侧边界场目录。

\texttt{starttime} 和 \texttt{endtime} 设置起止时间，格式为 \texttt{YYYYMMDDHH}。\texttt{ncpus} 设置使用的核心数。\texttt{job\_management\_system} 选择任务管理系统，可选 \texttt{lsf} 或 \texttt{slurm}；\texttt{ini} 指定配置文件路径。

\section{日志}

CPS 使用两级日志系统，主日志记录配置检查和模块调用情况，子日志记录各步骤的流程输出。运行失败时，可根据主日志中的报错位置查找对应的流程日志。

\subsection{主日志（Main Log）}

主日志默认保存在当前运行目录，文件名为：\linecode{DataPrepare.[GridName].log}，日志记录以下内容：

\begin{itemize}[leftmargin=4em]
    \item 程序启动与结束信息
    \item 配置文件的读取与参数解析结果
    \item 系统环境与路径检查结果
    \item 各预处理模块的开始和结束状态
    \item 外部程序调用命令（Debug 模式下）
    \item 错误信息与错误来源
\end{itemize}

日志级别如下：

\begin{itemize}[leftmargin=4em]
    \item \linecode{INFO}：步骤开始、结束及运行状态
    \item \linecode{DEBUG}：详细执行信息（仅在启用Debug模式时输出）
    \item \linecode{WARNING}：非致命问题提示
    \item \linecode{ERROR}：流程中断或执行失败信息
\end{itemize}


\subsection{流程日志（Process Logs）}

流程日志保存在案例输出目录下的 \linecode{CaseOutputPath/[GridName]/Log/} 中，文件名为：\linecode{log.<ProcessName>}，其中 \texttt{<ProcessName>} 为各步骤的名称，如 \texttt{Geogrid}、\texttt{Ungrib}、\texttt{Metgrid}、\texttt{Real} 等。


在涉及时间分片或多次调用的流程中，日志文件会附带时间标识或编号后缀。

流程日志主要记录：

\begin{itemize}[leftmargin=4em]
    \item 外部可执行程序（如 \linecode{geogrid.exe}）的标准输出
    \item 模型或工具自身产生的错误信息
    \item 一些步骤的后处理脚本输出
\end{itemize}

\subsection{日志与错误定位建议}

CPS 运行失败时，按以下顺序排查：

\begin{enumerate}
    \item 查看主日志，确认失败的流程阶段及路径（参见日志中 \texttt{Error at:} 提示）
    \item 查看对应流程日志，打开 \linecode{CaseOutputPath/[GridName]/Log/log.<ProcessName>}
    \item 检查流程日志中是否有外部程序报错信息，或提示缺少依赖库、文件路径错误等问题
    \item 若始终无法定位，开启 Debug 模式重试，有时候超算脑抽，可能重试就可以跑
\end{enumerate}
\begin{CPSNote}[Tips]
    若启用 \texttt{CleanTempFiles = True}，部分中间文件可能被自动删除；调试时请关闭该选项。
\end{CPSNote}


\subsection{常见错误排查建议}

\textbf{1. 找不到依赖库，例如 NetCDF}

\begin{itemize}[leftmargin=4em]
    \item 运行 CPS 前，先用 \texttt{source} 加载对应环境，再检查依赖库路径。若错误发生在 CPS 切换环境之后，可手动加载环境后重试。
\end{itemize}

\textbf{2. CWRF 制作 ICBC 数据失败}

\begin{itemize}[leftmargin=4em]
    \item 检查流程日志中的网格划分和 MPI 报错。若网格划分与核心数不匹配，调整分配的核心数后重试。
\end{itemize}

\textbf{3. CoLM 处理步骤失败}

\begin{itemize}[leftmargin=4em]
    \item 先查看对应步骤的流程日志。若提示找不到程序或依赖库，重新加载 CoLM 环境后重试。
    \item CoLM 的 define 选项需与目标实验配置一致，运行前应核对这些编译选项。
\end{itemize}

\section{一些常用技巧}

有些技巧可以帮助你更高效地使用 CPS：
\begin{itemize}[leftmargin=4em]
    \item CWRF和CoLM的基础数据和起止时间无关
    \item CPL7的权重文件和网格映射文件只需生成一次，后续可复用
    \item CoLM的restart文件只会有第一年的数据，无论你怎么指定时间，它都只会运行2天
\end{itemize}


\begin{CPSNote} [注意]
    在CRESM运行的普通案例中，我们一般建议用户运行一个离线的多年CoLM案例(不少于5年)，生成restart文件，然后再跑CRESM的耦合案例。
    CoLM的冷启动会显著影响模型精度。
\end{CPSNote}

\subsection{制作多年数据}
如果你是一个懒人，那你就乖乖将开始时间和结束时间设置成多年。
例如：\linecode{StartTime=2000-01-01\_00:00:00} 和 \linecode{EndTime=2023-12-31\_23:59:59}，然后运行 CPS。
CPS 会自动将多年数据分块处理，生成每年的 ICBC 数据。请注意CoLM的restart文件只会有第一年的冷启动数据。

\bigbreak

但是如果你想要更快的制作多年数据。请遵循以下步骤:
\begin{itemize}[leftmargin=4em]
    \item \linecode{step1}：将起止时间设置为3天，制作基础数据。
    \item \linecode{step1}：使用 \texttt{-y} 参数，指定年份，制作每年的 ICBC 数据，可以在提交多年任务加速。
    \item \linecode{step3}：使用 \texttt{-c} 参数，将每年的 ICBC 数据汇总到同一目录。
    \item \linecode{step4}：使用 \texttt{Create\_Run\_From\_CPS.py} 创建运行案例。
    \item \linecode{step5}：赋值一个colm的namelist，并配置离线实验，运行一个离线的多年CoLM案例(不少于5年)
    \item \linecode{step6}：将多年CoLM案例的restart文件复制到CRESM的耦合案例中。
    \item \linecode{step7}：运行CRESM的耦合案例。
\end{itemize}
